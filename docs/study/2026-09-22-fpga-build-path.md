# Study: the buildable path for a fun, open-source security OS on an FPGA

- **Date:** 2026-09-22
- **Goal (clarified):** a *fun*, open-source, security-flavored OS that boots on a real
  FPGA soft-core. Not a research flag — a real, hackable, enjoyable build. Findings only.

## Existence proof: Precursor / Betrusted
[Precursor](https://betrusted.io/) is an open-hardware security device that runs **Xous**
(Rust microkernel) on a **VexRiscv** soft-core, SoC generated by **LiteX**, on an FPGA
(Spartan-7), with LCD + keyboard. 100% open source; *"users can rebuild their own
softcore-CPU and OS."* This is the template for exactly this project.
([Antmicro](https://antmicro.com/blog/2020/12/precursor-and-renode))

## The stack (all open toolchain)
| Layer | Choice | Why |
|-------|--------|-----|
| Board | **ULX3S (ECP5-85F, ~$115-155)** | Fully open toolchain (yosys/nextpnr/verilator); proven to run RISC-V soft-cores and even Linux; huge tutorial base. |
| SoC builder | **LiteX** | Generates SoC around VexRiscv: DRAM, UART, SD, Ethernet, JTAG, **MMU option**. "Boring on purpose" scaffolding. |
| CPU | **VexRiscv** (RV32, MMU-capable) | Same core as Precursor/Baochip; FPGA-friendly; SpinalHDL. |
| OS | **fork Xous** *or* **from-scratch Rust microkernel** | This is where our fun + security lives. |

Refs: [ULX3S+LiteX](https://gojimmypi.github.io/risc-v-on-ulx3s-with-litex/),
[OS dev on ULX3S](https://x86.lol/generic/2020/12/30/riscv-ulx3s.html),
[linux-on-litex-vexriscv](https://github.com/litex-hub/linux-on-litex-vexriscv),
[Linux on ULX3S](https://blog.bomorgan.io/hobbies/hardware/fpgas/litex-riscv-ecp5-ulx3s/)

## What this de-risks
- Hardware bring-up (DRAM, clocking, peripherals) is solved by LiteX — we don't hand-write it.
- A CPU that runs a real OS (with MMU) already exists (VexRiscv) — we don't design a core to start.
- The whole toolchain is open and free — matches the open-source requirement end to end.

## The genuine fun-decisions (to discuss, not concluded)
1. **OS approach:** fork/port **Xous** (real security OS on the FPGA fast, then hack
   security features in) vs. **write our own minimal Rust microkernel** on LiteX (more
   "I built an OS from nothing," slower to feel real). Hybrid: get *something* booting on
   the FPGA first to de-risk, then choose.
2. **The "security fun" hook** — what makes it a *security* OS that's fun to show:
   candidates to explore — capability isolation you can *attack* live; visible
   compromise-containment (LEDs/screen say "attack contained"); a hardware RNG you can
   watch; secure boot you try to bypass; glitch/tamper detection (Baochip-style);
   an on-device "CTF target" you exploit and then watch the OS defend.
3. **Board purchase:** ULX3S (recommended) vs. Arty A7-100T (more headroom, closed Vivado
   toolchain).

## Open questions
- How much of the fun is *building the OS* vs. *having a security gadget to hack on*?
  (Decides fork-vs-scratch.)
- Does the FPGA need a screen/peripherals for the "fun" (ULX3S has HDMI, GPIO, SD; add a
  small SPI LCD like Precursor)?
