Architecture Specification · v1 · 2026-09

Redoubt

A hardware-rooted reference-monitor OS for AI agents — a tiny, inspectable, unbypassable trust anchor on an open RISC-V FPGA soft-core that mediates every tool call an agent makes, so a fully hijacked agent still cannot exceed its granted authority.

Target · ULX3S (ECP5-85F) ISA · RV32IMAC, M/S/U + PMP SoC · LiteX + VexRiscv Toolchain · yosys / nextpnr (open) TCB budget · ≤ 2,500 LoC

0The problem, plainly

An autonomous AI agent does something no earlier program did routinely: it takes attacker-influenceable instructions (a prompt, a web page, a tool's output) and, on the strength of them, acts — it calls tools, sends network requests, reads and writes files, spends credentials. The agent cannot reliably tell a legitimate instruction from a malicious one [8]. So we must assume the agent's reasoning can be hijacked at any moment, and design as if it already has been.

Every existing secure OS was built for a different kind of user. seL4, Qubes, and bunnie's Xous/Baochip all assume the principal has stable, honest intent and protect its secrets — they are vaults. An agent is the opposite case: it is simultaneously the user and the threat, and it runs untrusted tools as normal business. What's missing is not another vault but a hazmat lab: a place where a compromised agent can run, and still touch nothing it wasn't explicitly permitted to touch.

Redoubt is that hazmat lab, built as the smallest possible trustworthy core. The whole design follows from one commitment: the security decision is made by a tiny piece of non-AI logic, below the agent, that the agent cannot bypass.

1The mental model

Picture an embassy. Staff inside (the agent and its tools) can ask to send a cable or open the gate, but they never hold the keys or touch the wire themselves — a single guard at the one door checks every request against written orders and performs it on their behalf. Compromise the whole staff and the guard still won't send a cable to the wrong country. Redoubt is that guard, implemented in hardware-enforced silicon privilege.

Concretely: the language model and agent loop run on an ordinary host (they are far too heavy for a soft-core, and don't need to be trusted). Redoubt runs on the FPGA and owns the things that matter — the network egress, the storage, the secrets. The agent can only send Redoubt a structured request; Redoubt decides, then acts.

2Design principles

Each is earned from studying what works (Apple platform security [6], bunnie's Baochip [22], seL4 [18], the RISC-V TEE monitors [4][5]) — not assumed.

One load-bearing primitive

A single mechanism carries security: complete mediation of the agent→world boundary by a capability reference monitor. No pile of overlapping features. (Baochip's lesson: do more with less mechanism.)

Deterministic verdicts only

Decisions are made by non-AI logic over the structured tool call (tool id + typed args + labels), never by judging the agent's fuzzy reasoning [2][3][7]. This dissolves the "AI reviewing AI" trap.

The kernel is not most-trusted

The trust anchor is smaller than and more privileged than the OS above it. (Apple SPTM [6]; RISC-V M-mode security monitor — Keystone/Sanctorum [4][5].)

Least privilege + complete mediation

No ambient authority; every effect is checked; no side door. (Anderson's 1972 reference monitor: tamper-proof, always-invoked, verifiable [1].)

Inspectable & measured

The TCB is small enough to audit, its size is a tracked build-gated metric (§13), and the whole design is open source.

Honest about scope

Where a defense doesn't hold (side channels, the ESP32 firmware, host-side agent memory) the doc says so plainly rather than implying coverage.

3Threat model & trust tiers

We assume the adversary already holds the strong positions: A1 full agent hijack (arbitrary prompt/goal injection [8]); A2 malicious/poisoned tools on the host; A3 arbitrary host code including the USB driver; A4 full control of the U·T2 compartments; and, as a stretch goal, A5 a compromised S·T1 Warden. The security property must survive all of these.

Security property (the guarantee). For every external effect e on egress, there exists a capability c in the active session such that bind(c)=tool(e), predicate(c)(args(e)), and flow_ok(c, labels(e)) — and this holds for arbitrary behavior of the host, T2, and even a compromised T1. This is Anderson's reference-monitor guarantee [1] instantiated for a typed tool call and a hijackable agent.

Out of scope (v1) — stated, not hidden

  • Microarchitectural / timing side channels [9]; physical & fault-injection attacks [10].
  • FPGA bitstream authenticity (a v2 root-of-trust concern) and ESP32 firmware integrity (§11.1).
  • Host-side poisoning of the agent's own memory; multi-agent collusion; agent self-DoS.

4Privilege & isolation — RISC-V PMP

RISC-V has three privilege modes, most to least: Machine > Supervisor > User. Redoubt maps its trust tiers straight onto them: the Monitor in M, Warden in S, compartments in U. What makes that mapping enforceable — rather than a diagram — is Physical Memory Protection (PMP): a set of machine-mode-only registers that whitelist which physical address ranges S- and U-mode may touch [11][12]. Supervisor code cannot even read the PMP registers, so it cannot widen its own reach.

Each of up to 64 PMP entries pairs a pmpaddr register (holding address[33:2]) with an 8-bit config field packed four-per-pmpcfg CSR on RV32:

pmpcfg byte:  [7] L (lock)   [6:5] rsvd   [4:3] A (0 off, 1 TOR, 2 NA4, 3 NAPOT)
              [2] X          [1] W        [0] R
TOR entry i matches the range [ pmpaddr(i-1) , pmpaddr(i) )   — no alignment constraint

Redoubt uses TOR entries for the arbitrarily-sized regions, and requires the Smepmp extension [13] so a region can be denied to M-mode software too (defense-in-depth for the secret/egress regions); where unavailable it falls back to locked (L=1) rules. All entries are written and locked at boot before any T1/T2 code runs — a locked entry is immutable until hart reset [11], so even a later Warden compromise (A5) cannot re-map T0. This is exactly the Keystone security-monitor pattern: the M-mode monitor guards its own memory and the protected regions with PMP, reconfiguring on entry [4][5].

If the Sv32 MMU is enabled in Warden, it adds finer per-compartment U-mode isolation on top; PMP remains the wall around T0 either way [12][14].

5Boot & root of trust

Boot exists to answer one question before the agent ever runs: is the Monitor we're about to trust the one we intended? A tiny measured-boot ROM answers it, then the Monitor locks down the hardware while it still has sole control.

6The Monitor

The Monitor is the whole point of Redoubt — the guard at the one door. It is no_std Rust with a single documented unsafe module (CSR / PMP / MMIO). It satisfies the three reference-monitor properties [1]: always invoked (egress MMIO is M-only, so every effect needs an ecall into the Monitor — no other path exists), tamper-proof (its code, data, and the secret store sit in M-only PMP regions), and verifiable (small, single-purpose, measured, LOC-budgeted).

Entry ABI

A request enters via ecall from U-mode using the standard RISC-V calling convention [17]:

a7 = REDOUBT_MEDIATE (0x52440001)   a0 = ptr into SHARED_REQ   a1 = length
return:  a0 = status (below)        a1 = response length
ecall-from-U raises mcause=8 → M-mode trap dispatches on a7. No ecall reads
SECRETS or drives EGRESS directly; those happen only inside step 6.

Status / reason codes

0x00 ALLOW    0x10 DENY_NO_CAP   0x11 DENY_TOOL   0x12 DENY_ARG
0x13 DENY_FLOW  0x14 DENY_MALFORMED  0x15 DENY_REVOKED  0x20 ERR_EGRESS  0x2F ERR_INTERNAL

7Capabilities

A capability is an unforgeable ticket: holding it is the authority to do a specific thing, and you cannot manufacture one you weren't given. The agent never holds authority directly — it holds an opaque handle (an index) into a per-session capability space that lives inside the Monitor. A guessed or out-of-range handle resolves to an empty slot, which denies. The model follows seL4's discipline [18][19] but is deliberately flat and fixed-size — no capability-derivation-tree graph, no untyped-retype — to keep the TCB tiny.

8Policy language

The operator declares exactly what a session may do in a small declarative manifest. It is deliberately a total language — bounded predicates over typed fields, a fixed label lattice, no loops or general computation — so the compiled decision is guaranteed to terminate and the policy itself is auditable. The Monitor compiles it to fixed tables at session setup.

session "researcher" {
  capability web = net {
    tool   = "http.request"
    arg url    : url  where scheme == "https" and host in {"api.example.com"}
    arg method : enum where method in {"GET"}
    secret API_KEY inject-as header "Authorization"   # Monitor injects; agent never sees it
    result label = UNTRUSTED
    deny-if body carries SECRET
  }
  capability corpus = file {
    tool = "file.read"
    arg path : path where prefix "/corpus/"
    result label = UNTRUSTED
  }
}   # every other tool_id → DENY_NO_CAP

Each where clause compiles to (field_selector, op, operand_ref) triples; op ∈ {EQ, IN_SET, PREFIX, HOST_IN_SET, SCHEME_EQ, RANGE, LEN_LE} over an interned constant pool. Evaluation is the fixed loop of step 4.

9Information flow

Capabilities and predicates say which effects and which arguments; information flow says which data may go where. Redoubt tracks a minimal Denning lattice [23] at the boundary: confidentiality PUBLIC ⊑ SECRET and integrity UNTRUSTED ⊑ TRUSTED, two bits per value. Secrets the Monitor injects are SECRET and may enter only a sink the capability clears — never a PUBLIC one. Data returned from egress is stamped UNTRUSTED, telling the host it is attacker-controlled. Declassification happens only via an explicit capability, as in DIFC systems like HiStar and Flume [24][25].

Honest scope. Redoubt sees only what crosses the wire, so it enforces boundary IFC (what enters and leaves via tool calls). It does not track flows inside the host LLM and does not claim end-to-end IFC through the agent's reasoning. Boundary IFC is the part that is deterministic and checkable — so it is the part we enforce.

10Wire protocol

Requests arrive over USB CDC-ACM, COBS-framed [20] with a CRC32. The decisive design choice is that arguments cross as typed values, not text. When a filter and the code that consumes a value disagree about how to parse a string, you get bugs like the classic %2e SSRF filter bypass. Redoubt sidesteps the whole class by re-deriving security-relevant fields from a structured form rather than trusting host-side parsing.

11Egress & secrets

Network (§11.1) — the ESP32 is reachable only over an M-owned link inside EGRESS_MMIO; a U-mode driver may format a payload, but the send is a Monitor action applying the Net cap and injecting secrets. Honest caveat: the ESP32 firmware is in the egress path; a wired-Ethernet board (ECPIX-5/Colorlight) is the purist v2 upgrade where the Monitor owns the MAC directly.

Storage — the LiteSDCard controller is M-only; block I/O is gated by File caps (path-prefix + mode); file contents come back labeled UNTRUSTED.

Secrets — keys live in the M-only SECRETS region, loaded at boot; only inject-as exposes them into an effect, never to a caller (cf. Apple SEP key-wrapping [6]).

TRNG — a ring-oscillator entropy source with continuous NIST SP 800-90B health tests (Repetition-Count + Adaptive-Proportion) [21] feeds handle randomization and session keys.

13TCB & verification

The trusted computing base is the Monitor + the measured-boot ROM + the PMP configuration — nothing else. Warden, the compartments, the host stack, the ESP32, and the peripheral drivers are all outside it: they can crash the system but cannot change the security verdict. The size of that TCB is the headline metric and a build gate.

Budget

Monitor ≤ 2,500 LoC no_std Rust; BROM ≤ 300 LoC. CI runs tokei and fails the build over budget; the README publishes the current number.

For scale

Linux/Qubes trust millions of lines; seL4's verified kernel is ~8.7k C [18]. A trust base a single person can read in an afternoon is the deliverable — not a footnote.

Complete-mediation argument (sketch). Every egress effect must touch EGRESS_MMIO, which is M-only (PMP entries locked at boot, before T1/T2 run — Figs. 2–3). The only entry to M is the ecall ABI, which runs the six checks. Therefore no effect bypasses the checks, even under a Warden compromise (A5). A small formal model of the pipeline is future work.

15Limits & roadmap

What v1 does not do

  • Side channels / timing [9]; physical & fault-injection [10].
  • Bitstream authenticity; ESP32 firmware integrity.
  • Host-side agent-memory poisoning; multi-agent collusion; availability.

Roadmap

  • v2 RTL mediation gate — enforce caps in hardware on the egress bus, so even a compromised M-mode Monitor can't bypass it.
  • Wired-Ethernet egress; richer label lattices; a formal model of the decision pipeline.
