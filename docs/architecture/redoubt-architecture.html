Part I · Foundations

0Problem & motivation

An autonomous AI agent does something no earlier program did routinely: it takes attacker-influenceable instructions — a prompt, a fetched web page, a tool's output — and, on the strength of them, acts: it calls tools, sends network requests, reads and writes files, spends credentials. It cannot reliably distinguish a legitimate instruction from a malicious one [8]. We therefore assume the agent's reasoning can be hijacked at any moment and design as if it already has been.

Every existing secure OS was built for a different principal. seL4, Qubes, and bunnie's Xous/Baochip all assume the user has stable, honest intent and protect its secrets — they are vaults. An agent is the inverse case: it is simultaneously the user and the threat, and running untrusted tools is its normal mode of operation. The missing artifact is not another vault but a hazmat lab: an environment where a compromised agent can run and still touch nothing it was not explicitly permitted to.

Redoubt is that hazmat lab, built as the smallest possible trustworthy core. Every decision in this manual follows from one commitment: the security decision is made by a tiny piece of non-AI logic, situated below the agent, that the agent cannot bypass. The rest is engineering that commitment into open silicon.

Why not a software policy layer on Linux?

The current agent-security tools (Progent [2], IFC-for-agents [3], ActPlane [7], Governed-MCP, and the Microsoft/NVIDIA runtimes) implement exactly this kind of mediation — but in software, on Linux. Their reference monitor runs at the same or lower privilege than the multi-million line kernel it shares with the agent; a single local-privilege-escalation bug in that kernel voids the whole guarantee. Redoubt's contribution is to move the monitor below the agent runtime into a small, inspectable, hardware-enforced trust anchor — so the guarantee holds even if the agent and the OS above it are fully compromised.

1System overview & components

The mental model is an embassy. Staff inside — the agent and its tools — can ask to send a cable or open the gate, but they never hold the keys or touch the wire; a single guard at the one door checks each request against written orders and performs it on their behalf. Compromise the whole staff and the guard still won't send a cable to the wrong country. Redoubt is that guard, implemented as the most-privileged code on the chip.

The language model and agent loop run on an ordinary host — too heavy for a soft-core, and deliberately untrusted. Redoubt runs on the FPGA, owns the network egress, storage, and secrets, and exposes only a narrow request interface.

2Design principles

Earned from studying what works — Apple platform security [6], Baochip [22], seL4 [18], the RISC-V TEE monitors [4][5] — not assumed.

One load-bearing primitive

Security rests on a single mechanism — complete mediation of the agent→world boundary by a capability reference monitor — not a pile of overlapping features. Implication: every other subsystem exists only to make that one mechanism unbypassable, small, and correct.

Deterministic verdicts only

Decisions are made by non-AI logic over the structured tool call (tool id + typed args + labels), never by judging the agent's reasoning [2][3][7]. Implication: no model, heuristic, or classifier sits on the decision path; the same input always yields the same verdict.

The kernel is not most-trusted

The trust anchor is smaller than and more privileged than the OS above it (Apple SPTM [6]; Keystone/Sanctorum M-mode monitors [4][5]). Implication: a Warden (S) compromise must not breach the Monitor (M).

Least privilege + complete mediation

No ambient authority; every effect is checked; no side door (Anderson 1972 [1]). Implication: a fresh session can do nothing until a capability is granted.

Inspectable & measured

The TCB is small enough to audit, its size is a build-gated metric (§20), the Monitor is measured at boot, and the design is open.

Honest about scope

Where a defense does not hold — side channels, the ESP32 firmware, host-side agent memory — the manual says so (§21) rather than implying coverage.

3Conventions & terminology

  • XLEN = 32. VexRiscv is a 32-bit core; all addresses and registers are 32-bit.
  • Endianness. All multi-byte on-wire and in-memory fields are little-endian (RISC-V native) unless stated.
  • Bit ranges are written [hi:lo], inclusive.
  • Tiers T0–T2 and modes M/S/U are defined in §5.
  • "Effect" = an externally observable action on egress (a network send, a storage write, a secret use). Mediation is defined over effects.
  • "Session" = one bounded run of one agent, with its own capability space and epoch (§17).
  • Citations [n] resolve in §28.

Part III · Hardware substrate

6Privilege & isolation — RISC-V PMP

RISC-V has three privilege modes, most to least: Machine > Supervisor > User. Redoubt maps its tiers straight onto them. What makes that mapping enforceable rather than decorative is Physical Memory Protection (PMP): machine-mode-only registers that whitelist which physical ranges S- and U-mode may access [11][12]. S-mode cannot even read the PMP registers, so it cannot widen its own reach.

Up to 64 entries; each pairs a pmpaddr register (holding address[33:2]) with an 8-bit config field packed four-per-pmpcfg CSR on RV32:

pmpcfg byte:  [7] L (lock)   [6:5] rsvd   [4:3] A (0 off · 1 TOR · 2 NA4 · 3 NAPOT)
              [2] X          [1] W        [0] R
TOR entry i matches [ pmpaddr(i-1), pmpaddr(i) )     — no alignment constraint
Lock (L=1): rule enforced on ALL modes incl. M, and immutable until hart reset
Smepmp:     lets a rule be enforced on non-M and denied to M without the all-modes lock

Redoubt uses TOR for the arbitrarily-sized regions and requires Smepmp [13] so the secret/egress regions can be denied to M-mode software too (defense-in-depth against a Monitor bug); where Smepmp is unavailable it falls back to locked (L=1) rules for the S/U-visible regions. All entries are written and locked at boot before any T1/T2 code runs. This is the Keystone security-monitor pattern: the M-mode monitor guards its own and the protected regions with PMP, reconfiguring on entry [4][5].

7.2 Clocking & reset

A single PLL derives the system clock (target ~50 MHz on ECP5, comfortably met by VexRiscv). Reset is synchronous; on reset the hart enters M-mode at 0x0 (BROM). The ESP32 has its own clock domain and is treated as an asynchronous peripheral behind a FIFO in EGRESS_MMIO.

8Boot & root of trust

Boot answers one question before the agent runs: is the Monitor we are about to trust the one we intended? The measured-boot ROM answers it, then the Monitor locks the hardware while it still has sole control.

8.1 Detailed sequence

1. ECP5 configures from QSPI bitstream (bitstream authenticity = v2; noted §21).
2. Hart resets into M-mode @ 0x0 (BROM).
3. BROM computes H = BLAKE2s-256(MON_CODE)         [15]
   and compares to H_expected (BRAM constant, baked with the bitstream).
   H ≠ H_expected → drive OLED "BOOT FAIL", halt.
4. BROM jumps to MON_CODE entry. Monitor:
   a. program pmpaddr/pmpcfg for entries 0..6 (Fig 2); set L / Smepmp; fence.
   b. load SECRETS from an M-only QSPI area; zeroize the staging buffer.
   c. init RO-TRNG; run NIST 800-90B start-up health tests (§19).            [21]
   d. compile the policy manifest into decision tables in MON_DATA (§13).
   e. set mtvec; leave ecall-from-S/U NOT delegated in medeleg (they trap to M).
5. Monitor mret → Warden (S). Warden starts Endpoint + drivers (U).
6. Session setup (§17) populates the first capability space from the manifest.

Attestation (v1). The head of the audit hash-chain (§10.4) and H can be read out over USB, letting an external verifier confirm both the Monitor image and the decision history. Remote attestation with a hardware-bound key is a v2 item.

Part IV · The trusted core

9Monitor structure & runtime

The Monitor is no_std Rust with a single documented unsafe module (CSR / PMP / MMIO). It satisfies the three reference-monitor properties [1]: always invoked (egress MMIO is M-only, so every effect needs an ecall), tamper-proof (code, data, and secrets in M-only PMP regions), and verifiable (small, single-purpose, measured, budgeted).

9.1 Runtime discipline

  • No heap on the hot path. All request-time state is fixed-size and preallocated; the request buffer is bounded (MAX_REQ = 512 B, MAX_ARGS = 8). This bounds worst-case time and removes allocator failure modes from the TCB.
  • Single-threaded, run-to-completion. The Monitor services one mediation at a time; there is no in-Monitor concurrency, so no locks and no data races in the TCB. Warden serializes requests.
  • Reentrancy. The egress step may block on hardware (ESP32/SD); the Monitor uses a bounded poll with a watchdog and returns ERR_EGRESS on timeout rather than spinning.
  • Stack. A dedicated M-mode stack in MON_DATA with a guard page (PMP sub-region) to trap overflow.

9.2 Trap handling

mtvec points at the Monitor's trap vector. Causes handled: ecall-from-U (8) and ecall-from-S (9) → mediation/relay dispatch on a7; access faults from M-only regions raised by T1/T2 are impossible (they fault in their own mode) — a fault reaching M indicates a Monitor bug and triggers a safe halt with a logged code.

11The decision pipeline

11.1 Reference algorithm

fn mediate(req_ptr, req_len) -> Status {
  // 1 bounds/format
  if !within(req_ptr, req_len, SHARED_REQ) || req_len > MAX_REQ { return DENY_MALFORMED }
  let r = parse_fixed(req_ptr, req_len)?;            // magic, counts ≤ MAX_ARGS, else DENY_MALFORMED
  // 2 capability + epoch
  let s = sessions.get(r.session_id).ok_or(DENY_NO_CAP)?;
  let cap = s.cspace.get(r.cap_handle).ok_or(DENY_NO_CAP)?;
  if cap.ctype == Empty || cap.epoch != s.epoch { return DENY_NO_CAP /*or REVOKED*/ }
  // 3 tool binding
  if cap.tool_id != r.tool_id { return DENY_TOOL }
  // 4 typed-argument predicate (fixed loop ≤ MAX_CLAUSES)
  for clause in pred_table[cap.pred_ref] {
      if !eval(clause, r.args) { return DENY_ARG }
  }
  // 5 information flow
  if !flow_ok(flow_table[cap.flow_ref], r.in_labels, cap) { return DENY_FLOW }
  // 6 perform (M-owned engine); inject bound secret; label result
  let out = egress_perform(cap, r.args)?;            // ERR_EGRESS/ERR_TIMEOUT on hw failure
  write_response(ALLOW, out, label_of(cap));
  audit_append(r, ALLOW);
  ALLOW
}

Complexity. Steps 1–5 are O(n_args × clauses) ≤ MAX_ARGS × MAX_CLAUSES (64), no allocation, no unbounded loops. The Monitor therefore always terminates — a prerequisite for the reference-monitor property.

12Capability system

A capability is an unforgeable ticket: holding it is the authority to do a specific thing. The agent holds only an opaque handle (an index) into a per-session capability space inside the Monitor; a guessed/out-of-range handle resolves to Empty → deny. Modeled on seL4's discipline [18][19] but deliberately flat and fixed-size (no derivation-tree graph, no untyped-retype) to keep the TCB tiny.

12.1 Cap layout (16 bytes)

struct Cap {                 // 128 bits, cf. seL4's 16-byte slots [18]
  ctype:u8      // 0 Empty · 1 Net · 2 File · 3 Secret · 4 Tool
  rights:u8     // per-type permission bits; derivation may only CLEAR bits
  tool_id:u16   // bound tool (0 = n/a)
  pred_ref:u16  // → predicate_table (0xFFFF = none)
  flow_ref:u16  // → flow_table
  secret_ref:u16// → secret store (0xFFFF = none; inject-only)
  aux:u16       // type-specific (e.g. allowlist_ref)
  epoch:u16     // must equal session.epoch else stale (revocation)
}

12.2–12.5 Operations

resolve(handle)
bounds-check into cspace; Empty/stale → DENY_NO_CAP. O(1).
cap_derive(src, narrower_pred)
new slot whose predicate is a compile-checked subset of src's; rights may only clear bits. No widening — rights amplification is structurally impossible.
revoke(session)
bump session.epoch; all old-epoch caps go stale in O(1) (a coarse but tiny alternative to seL4's CDT walk [19]).
secrets (use-only)
a Secret cap lets the Monitor inject a secret into an effect; no operation returns its bytes to any caller (cf. SEP key-wrapping [6]).

13Policy model & compiler

The operator declares what a session may do in a small declarative manifest. It is a total language — bounded predicates over typed fields, a fixed label lattice, no loops or general computation — so the compiled decision always terminates and the policy is auditable.

13.1 Grammar (EBNF)

manifest   = "session" STRING "{" { capability } "}" ;
capability = "capability" IDENT "=" captype "{" { clause } "}" ;
captype    = "net" | "file" | "secret" | "tool" ;
clause     = "tool" "=" STRING
           | "arg" IDENT ":" argtype "where" predicate
           | "secret" IDENT "inject-as" injsite
           | "result" "label" "=" label
           | "deny-if" flowcond
           | "quota" INT ("per" duration)? ;
argtype    = "url" | "path" | "enum" | "int" | "bytes" ;
predicate  = pterm { ("and"|"or") pterm } ;      pterm = field op operand ;

13.2 Compiled forms

Each arg … where … compiles to an array of clauses (field_selector, op, operand_ref) where op ∈ {EQ, IN_SET, PREFIX, SUFFIX, HOST_IN_SET, SCHEME_EQ, RANGE, LEN_LE} and operand_ref indexes an interned constant pool (allowlists, ranges) in MON_DATA. flowcond compiles to a flow rule (§14). The compiler statically verifies subset relationships for cap_derive and rejects any predicate that is not total.

13.3 Example → tables

capability web = net {
  tool = "http.request"
  arg url    : url  where scheme == "https" and host in {"api.example.com"}
  arg method : enum where method in {"GET"}
  secret API_KEY inject-as header "Authorization"
  result label = UNTRUSTED
  deny-if body carries SECRET
  quota 100 per minute
}
compiles to:  Cap{ctype:Net, tool_id:H("http.request"),
                  pred_ref:P, flow_ref:F, secret_ref:S(API_KEY), aux:allow_ref}
  pred_table[P] = [ (url.scheme, SCHEME_EQ, "https"),
                    (url.host,   HOST_IN_SET, allow_ref),
                    (method,     IN_SET, {GET}) ]
  flow_table[F] = { inject: {API_KEY→SECRET}, deny: SECRET→PUBLIC_SINK }

14Information-flow control

Capabilities and predicates say which effects and which arguments; information flow says which data may go where. Redoubt tracks a minimal Denning lattice [23] at the boundary.

Confidentiality:  PUBLIC ⊑ SECRET          Integrity:  UNTRUSTED ⊑ TRUSTED
Label = 2 bits (C,I) carried per TypedArg and per result (in_labels / out_labels)
Rules (step 5):
  • SECRET value may enter an effect only if cap.flow clears that sink; never a PUBLIC sink
  • egress results are stamped UNTRUSTED (propagate to host: treat as attacker-controlled)
  • declassification (lowering C) requires an explicit cap — no implicit declassification  [24][25]
Honest scope. Redoubt sees only what crosses the wire, so it enforces boundary IFC (what enters/leaves via tool calls). It does not track flows inside the host LLM and does not claim end-to-end IFC through the agent's reasoning. Boundary IFC is the deterministic, checkable part — so it is the part we enforce.

Part V · The untrusted stack

15Warden — scheduling & IPC (S-mode)

Warden is a minimal S-mode microkernel. It is T1: trusted for liveness, not for the security verdict. A Warden compromise (A5) must not breach the Monitor — which holds because the Monitor's regions are M-only PMP (§6) and the verdict runs in M.

15.1 Responsibilities

  • Threads & scheduling. A small round-robin scheduler with timer preemption (stimecmp / SBI timer). Each compartment is one or more threads.
  • Address spaces. If Sv32 is enabled, Warden manages per-compartment page tables for U-mode isolation on top of PMP; otherwise compartments are separated by PMP sub-regions.
  • IPC. Synchronous message-passing over endpoints (rendezvous): a sender blocks until a receiver is ready. Bounded message size; the kernel copies by value (no shared writable pages between compartments in v1).
  • ecall relay. Warden marshals a compartment's mediation request into SHARED_REQ and issues the M-mode REDOUBT_MEDIATE ecall on its behalf, then returns the response.
  • Session calls. Warden invokes SESSION_OPEN/REVOKE/CLOSE (§10) at the Monitor on operator instruction.

15.2 Why IPC is synchronous

Rendezvous IPC has no kernel-side buffering, no queue management, and no allocation — the smallest correct design, following seL4 [18]. Throughput is not the goal; a small, obviously-correct T1 is.

16Compartments & drivers (U-mode)

Compartments are ordinary U-mode processes, each in its own PMP/MMU region, with an empty capability space except what the Monitor installs. They can crash without affecting the verdict.

CompartmentDoesCannot
Endpointde-frames USB (COBS/CRC, §18), forwards typed requests via Warden→Monitordecide a verdict; touch secrets/egress
Net driverformats HTTP/TLS payloads for the ESP32 linksend — the send is a Monitor action
Storage driverprepares SD block requestscommit — the write is a Monitor action

The split is deliberate: drivers do the bulky, bug-prone formatting work in untrusted U-mode, while the Monitor does only the small authority-bearing step. A driver compromise buys the attacker nothing it did not already have as the (untrusted) host.

17Session lifecycle

A session is one bounded run of one agent, with its own capability space and epoch. Sessions are how Redoubt scopes authority in time — revoke a session and every capability it held goes stale at once.

  • Created → Provisioned: SESSION_OPEN compiles the named manifest and installs its capabilities into a fresh, otherwise-empty cspace.
  • Provisioned → Active: the Endpoint binds the session to a host connection.
  • Active: each request runs the pipeline (§11). A per-session quota (from the manifest) is decremented; exhaustion → DENY_QUOTA.
  • Active → Draining/Destroyed: SESSION_REVOKE bumps the epoch (instant staling); SESSION_CLOSE tears down after in-flight requests complete.

Part VI · I/O & egress

18Wire protocol

Requests arrive over USB CDC-ACM, COBS-framed [20] with CRC32. The decisive choice is that arguments cross as typed values, not text — closing the class of bugs where a filter and the consumer disagree on parsing (e.g. the %2e SSRF bypass).

18.1 Framing & errors

COBS gives an unambiguous zero-delimiter; crc32 (IEEE) covers ver…payload. Bad CRC/COBS → frame dropped, a counter incremented, no partial processing. ver gates protocol evolution; an unknown ver is rejected.

19Egress & secrets

Network. The ESP32 is reachable only over an M-owned link in EGRESS_MMIO; the U-mode net driver formats payloads, but the send is a Monitor action applying the Net cap and injecting secrets. Honest caveat: the ESP32 firmware is in the egress path; a wired-Ethernet board (ECPIX-5/Colorlight) is the purist v2 upgrade where the Monitor owns the MAC.

Storage. LiteSDCard controller is M-only; block I/O gated by File caps (path-prefix + mode); contents returned come back labeled UNTRUSTED.

Secrets. Keys live in the M-only SECRETS region, loaded at boot; only inject-as exposes them into an effect, never to a caller (cf. SEP key-wrapping [6]).

TRNG. Ring-oscillator entropy with continuous NIST SP 800-90B health tests (Repetition-Count + Adaptive-Proportion) [21]; on failure, entropy-consuming operations block.

Part VII · Assurance

20TCB accounting

The TCB is Monitor + BROM + PMP config — nothing else. Warden, compartments, host stack, ESP32, and peripheral drivers are outside it: they can crash the system but cannot change a verdict. TCB size is the headline metric and a build gate.

Budget & gate

Monitor ≤ 2,500 LoC no_std Rust; BROM ≤ 300. CI runs tokei over the trusted crates and fails the build over budget; the README publishes the current number.

For scale

Linux/Qubes trust millions of lines; seL4's verified kernel is ~8.7k C [18]. A trust base one person can read in an afternoon is the deliverable.

21Security analysis

21.1 Complete-mediation argument (sketch)

Every egress effect must touch EGRESS_MMIO, which is M-only (PMP entries locked at boot, before T1/T2 run — §6, §8). The only entry to M is the ecall ABI (§10), which runs the six checks (§11). Therefore no effect bypasses the checks, even under a Warden compromise (A5). Secret confidentiality follows from SECRETS being M-only and no ABI returning secret bytes (§12.5). A small formal model of the pipeline and a machine-checked mediation proof are future work (§26).

22Verification & test plan

  • Host unit tests — capability-table ops, PMP-address math, predicate evaluation, label lattice, wire (de)framing, compiled against the host target.
  • Verilator SoC sim — run the Monitor+Warden on a simulated VexRiscv; assert PMP faults when T1/T2 touch M-only regions (the isolation invariant).
  • QEMU integration — headless boot; scenario-driven; assert on status codes / console: test_boot, test_mediate_roundtrip, and the containment suite below.
  • Containment suite (the point) — for each attack in the §4 tree, assert the exact DENY_* and that no egress occurred: deny_host, deny_flow_secret, deny_forged_handle, fault_egress_from_U, fault_tamper_monitor.
  • Fuzzing — fuzz the Endpoint's frame parser and the TypedArg decoder (untrusted input), with ASan on the host build; the Monitor's parser is fuzzed against MAX_REQ bounds.
  • CI gates — TCB LoC ≤ budget; all containment tests green; no unsafe outside the one sanctioned module (checked by cargo-geiger).

26Roadmap

  • v2 · RTL mediation gate — a LiteX peripheral on the egress bus enforcing caps in hardware, so even a compromised M-mode Monitor cannot bypass it (the distinctive silicon).
  • Wired-Ethernet egress (ECPIX-5 / Colorlight) so the Monitor owns the MAC directly.
  • Formal model of the decision pipeline; machine-checked complete-mediation proof.
  • Richer IFC lattices; multi-session concurrency; remote attestation with a hardware-bound key; bitstream authenticity RoT.

27Glossary

Reference monitor
A component that is always invoked, tamper-proof, and small enough to verify, mediating all security-relevant operations [1].
PMP
Physical Memory Protection — M-mode-only RISC-V registers whitelisting physical access for lower modes [11].
Smepmp
PMP extension allowing a region to be denied to M-mode without the all-modes lock [13].
Capability
An unforgeable reference that is the authority to perform a specific operation.
Session / epoch
A bounded agent run; bumping its epoch revokes all its capabilities at once.
Compartment
An isolated U-mode process with no ambient authority.
Boundary IFC
Information-flow control enforced on data crossing the tool-call boundary (not inside the host LLM).
TCB
Trusted Computing Base — here, Monitor + BROM + PMP config.
